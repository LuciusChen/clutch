# Delimited export preserves NULL and offers defaults

Issue #121's follow-up showed that CSV exported SQL NULL and literal `NULL` text identically. The existing display formatter deliberately renders nil as `NULL`; sharing that presentation with delimited data lost the distinction. CSV has no universal SQL NULL value, so Clutch defaults to the PostgreSQL COPY CSV convention: an unquoted empty field is SQL NULL, quoted empty text is an empty string, and other text stays literal. CSV and TSV copy and both export paths use the existing shared escaping function. Consumers must use the documented convention; this does not change the grid or insert-form import semantics.

One option lets the consumer choose another NULL marker, following the locally verified DataGrip formatter behavior. SQL NULL is never quoted, and ordinary text equal to the marker is. No quoting policy is offered: issue #121 did not ask for one, and writing values unquoted lets separators split them and makes text equal to the marker indistinguishable from NULL. Custom quote characters and escape languages are outside this change. The existing escaping function owns these rules without another formatter or export configuration object.

Export defaults belong to the existing prompts. Three options select the query format and file destination defaults; encoding reuses its existing option. No persistent export profile, remembered mutable destination or additional command is needed. Unset destination options preserve the buffer's directory and each format's default file name; a configured name is offered as written. The directory applies to every file export, and the file name only to CSV and TSV exports, whose formats it names; INSERT and UPDATE exports keep their own. Buffer-local bindings permit project-specific choices, while the prompts and overwrite confirmation keep their existing behavior.

The existing CSV, TSV and real SQLite query-export regressions failed before the NULL fix and pass after it, checking NULL, empty text, literal NULL and BOM handling across pages. The CSV and default-settings regressions were extended for custom NULL text, failed on the preceding PR commit and pass with the options implemented. The default-settings regression runs actual SQLite query export and result file export with RET answers, checking both original defaults and configured format, encoding, directory and file name, and that an INSERT export is offered its own file name. Native PostgreSQL/MySQL direct export covers both default and custom NULL markers; the existing wide cross-backend fixture covers the default convention without another fixture. No additional test was needed for this extension.

The separate wide-export performance report remains under investigation. This change adds no cursor, transport path or performance claim.

The localhost relay test skipped in the sandbox and passed when rerun outside it on all three versions. The complete native/JDBC runner passed 15 suites, with 249 passes, 223 capability skips and no failures. It used disposable databases, ClickHouse 24.8 and the pinned agent 0.2.26 with its verified checksum in an isolated runtime. The existing wide CSV/TSV export fixture passed on PostgreSQL, MySQL, Oracle, SQL Server and DuckDB.
