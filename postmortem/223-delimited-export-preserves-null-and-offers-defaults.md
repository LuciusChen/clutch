# Delimited export preserves NULL and offers defaults

Issue #121's follow-up showed that CSV exported SQL NULL and literal `NULL` text identically. The existing display formatter deliberately renders nil as `NULL`; sharing that presentation with delimited data lost the distinction. CSV has no universal SQL NULL value, so Clutch now follows the PostgreSQL COPY CSV convention: an unquoted empty field is SQL NULL, quoted empty text is an empty string, and other text stays literal. CSV and TSV copy and both export paths use the existing shared escaping function. Consumers must use the documented convention; this does not change the grid or insert-form import semantics.

Export defaults belong to the existing prompts. Three options select the query format and file destination defaults; encoding reuses its existing option. No persistent export profile, remembered mutable destination or additional command is needed. Unset destination options preserve the buffer's directory and each format's default file name; a configured name is offered as written. Buffer-local bindings permit project-specific choices, while the prompts and overwrite confirmation keep their existing behavior.

The existing CSV, TSV and real SQLite query-export regressions failed before the NULL fix and pass after it, checking NULL, empty text, literal NULL and BOM handling across pages. The default-settings regression runs actual SQLite query export and result file export with RET answers, checking both original defaults and configured format, encoding, directory and file name. Native PostgreSQL/MySQL direct export and the existing wide cross-backend fixture cover the changed output convention without another fixture.

The separate wide-export performance report remains under investigation. This change adds no cursor, transport path or performance claim.

The full non-live gate passed on Emacs 29.4, 30.2 and 32.0.50: each ran 708 main tests, 284 backend tests and 13 architecture tests, with zero compilation, package-lint or checkdoc warnings. The complete native/JDBC runner passed 15 suites, with 249 passes, 223 capability skips and no failures. It used disposable databases, ClickHouse 24.8 and the pinned agent 0.2.26 with its verified checksum in an isolated runtime. The existing wide CSV/TSV export fixture passed on PostgreSQL, MySQL, Oracle, SQL Server and DuckDB.
