# Native isearch reaches result headers

Result column names previously existed only in `header-line-format`, outside searchable buffer text. ETAF's useful precedent is its real buffer header plus a fixed copy: native isearch reaches the real text, rather than searching the displayed header-line string. Reuse this arrangement without bringing in ETAF or adding a window. The earlier overlay-only experiment is a separate branch and is not part of this implementation.

The optional `clutch-result-searchable-header-mode` inserts a real first row built by the existing header renderer. Data rows retain their own row/cell properties and positions; the header receives column identity only. Truncated column names keep their complete raw text with the fitted label as a display replacement, allowing native isearch to match the complete name while preserving cell width. No search advice, remapped search command, duplicate search index or synthetic data row is needed.

Window-local header-line parameters suppress the fixed copy while that window's point is in the real header. Returning to data restores the previous parameter and starts the viewport after the real row. Switching buffers, disabling the mode and killing the result restore the window's previous setting. Search therefore follows ordinary buffer order: backward search reaches headers from data, forward search reaches them after wrapping, and matching data values remain ordinary matches. `RET` keeps the match, `C-g` restores search origin, and the existing `n` command enters the same column's first data row from a header.

Keep the header's mouse keymap but omit its header-line-only `local-map` replacement in buffer text: carrying that property into the buffer hid the result's normal keyboard bindings and made `n` try to insert text. A failing regression reproduced this before the property was corrected. Header text refresh uses `replace-region-contents` to retain search markers and point when names stay unchanged; full redraws retain header context even at its non-column prefix.

When the fixed copy is hidden it cannot run its usual font-metric check, so a buffer-local post-command hook and `text-scale-mode-hook` schedule the existing metric refresh while point is in the real header. Preserving header context across that refresh and rerendering with current metrics keeps columns aligned after text scaling. The check must not run from `pre-redisplay-functions`: on macOS GUI Emacs `string-pixel-width` measures against the window's glyph matrix, and doing so while the real header occupies the first text row interferes with cursor drawing, leaving the cursor zero pixels wide after the blink turns it off. The redisplay hook therefore only switches the window's header copy and viewport, and disabling the mode removes both added hooks.

The feature remains opt-in. It does not replace the default header-line renderer or make only headers searchable. Enabling the mode in a result lasts until the major mode is initialized again, which every query does; `clutch-result-searchable-header` enables it in each subsequent result. Native text selection can include header text, while Clutch's row selection and mutation logic continue to operate on data identities. Backend protocol, query and export paths are unchanged.

Validation covered Emacs 29.4/30.2/32.0.50: the non-live gate (compilation, lint, checkdoc, main, backend and architecture tests), the native live matrix with the mode enabled in result-mode hooks, and GUI search, abort and alignment checks at two text scales and three horizontal offsets. A focused regression fails when the font check returns to pre-redisplay, and an Emacs 32 GUI probe showed the cursor width alternating 7/0 pixels after the fix rather than staying 0 in the header. On a 500 x 30 result the mode cost under 4% on cell navigation and full render against the default.
