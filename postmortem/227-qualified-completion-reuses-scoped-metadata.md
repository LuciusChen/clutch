# Qualified completion reuses scoped metadata

Issue #167 needs table and column completion outside the current schema without changing the query session or eagerly scanning every accessible schema. Explicit `schema.` table references and qualified source tables select the scope; unqualified completion keeps its existing behavior.

Scoped table names and column names live in the existing per-connection table metadata cache. Existing request tickets own loading, failure and stale-response rejection, and existing namespace refresh and connection replacement invalidate the cache. There is no second cache, schema preload option or session state object. Native PostgreSQL and MySQL requests use their public asynchronous protocol APIs. JDBC uses scoped metadata RPCs, including asynchronous cursor continuation when table names exceed the first batch.

Column completion requests names rather than detailed key metadata. Live verification showed that MySQL's existing detailed-column path did not honor a supplied schema. DuckDB and SQL Server metadata use LIKE patterns, so this completion path escapes literal underscores, percent signs and backslashes; two colliding schema names and table names protect this boundary in the live test.

The supported scope is PostgreSQL, MySQL, Oracle, SQL Server and DuckDB within the connection's catalog. Cross-catalog table enumeration is declined rather than silently using the current catalog. Existing lightweight SQL recognition limits remain; this change does not introduce a full SQL parser.

Disposable live databases verified table and alias column completion, same-named sources in different schemas, literal pattern characters, unchanged resolution context and cache reuse on all five backends. The new focused completion test fails against the previous product code. Performance probes used three schemas with 100 tables and 20 columns each: six initial metadata requests, no additional requests during 600 hot completions, and mean hot completion time approximately 0.09–0.31 ms. With a simulated 50 ms database round trip, Oracle cold column metadata took approximately 1.28 seconds; this is asynchronous availability latency, not a promise that metadata arrives immediately. An additional Oracle probe with 1,001 tables exercised cursor continuation. Performance probes are temporary measurements rather than permanent benchmark fixtures; the retained live fixture concentrates on correctness boundaries.

Review of the first implementation found four real regressions: synchronous SQLite scoped columns were routed to an unsupported async method, quoted direct qualifiers lost normalization, eldoc still consumed bare-table cache keys, and synchronous request dispatch errors could leave a loading ticket. Four focused tests fail on c873675 and pass after correction, including a real in-memory SQLite database. The SQLite adapter returns local scoped column names immediately, while network adapters remain asynchronous; eldoc consumes scoped names and details while retaining current-schema cached details; and the existing request owner settles dispatch errors through the same failure callback used for asynchronous errors. Dead connections do not start scoped requests. No new recovery or cache owner was added.


A second review caught two issues in e22be1c. Reusing bare-table metadata called current-schema from completion and eldoc; DuckDB implements that operation with a synchronous query. These paths now compare the namespace already recorded in the buffer's connection render state. A real file-backed DuckDB probe fails on e22be1c with two namespace reads during completion/eldoc and passes after correction with none. An initial in-memory probe could not share its schemas with the separate metadata session, so the user guide states the file-backed limitation.

MySQL's detailed-column method and its primary/foreign-key methods ignored an explicit schema. A disposable live fixture with same-named tables proves that e22be1c returns the current database's int instead of the requested database's varchar(17); the fix returns the requested type, comment, primary key and foreign key without changing the current database. Existing methods now consistently forward the explicit schema, and omitted schema retains DATABASE() behavior. The complete 15-suite native/JDBC matrix passes with 251 passes and 224 capability skips; Emacs 29.4, 30.2 and 32 non-live gates pass. No cache or namespace state was added.
