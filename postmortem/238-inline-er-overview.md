# A compact overview above the table details

## Integrated overview

Keep the existing table name, summary, rule and field relations together below a compact overview. The first table anchors the overview, and the table whose fields are shown is highlighted. Table buttons share the existing asynchronous table loader. Direction keys move one projection node, and RET or a mouse click opens its table. Field details serve as a display. The independent back command and history are removed. Each completed table load contributes its relation list to buffer-owned overview state associated with that connection. Columns stay with the existing model and metadata caches. Manual-relation edits clear remembered adjacency so removed links disappear from the overview.

Draw a horizontal branching projection with at most twelve visible nodes. Merge links between the same tables, combining direction where needed. Already displayed nodes terminate as labelled references, representing cycles and cross-links without crossing strokes. A plus sign marks a collapsed node. Ordinary node navigation retains the root and expanded-node set, so arriving metadata changes the details and current highlight while preserving the overview's text and positions. Labels keep the same characters when selection changes. Point returns to the selected node during loading and after completion. The loading view keeps the same leading newline as the ready view.

Explicit `+` expands a table through the same reader, using already known relations for a visited table. `C-u g` explicitly recenters, and a destination outside the width/node budget recenters automatically so it remains visible. This replaces the initial prototype's automatic rerooting and expansion on every table switch, which the user found disorienting. One buffer-local list records the root and explicitly expanded entries. Completed loads capture canonical relation destinations once, including the connection namespace of unqualified manual endpoints. Rendering reuses that snapshot.

## Font evidence

The user's PragmataPro glyph advances are 7 pixels for box strokes and 14 pixels for arrows even though both report a one-column character width. Logical-column indentation therefore misaligns nested branches. The overview records each junction's measured display position and uses Emacs display-space alignment for subsequent stems. Terminal drawing retains character columns. Existing glyph-metric arrow baseline alignment is reused, and the ER buffer uses zero added line spacing.

Actual GUI verification checked matching branch origins at 98 and 189 pixels at the user's original scale, and 126 and 242 pixels one scale step larger. The temporary scale was restored. Mouse activation was verified on the local PG demo, including asynchronous table loading and current-table tracking. Keyboard table buttons preserve TAB for column visibility. A terminal Emacs run also displayed the same overview and details.

## Performance and checks

A first transient adjacency implementation used association-list lookup and took 564 ms for 10,000 distinct neighbours. A transient hash table preserves relation order and reduces that case to 7.62 ms in compiled code. The compiled overview averaged 0.14 ms with 100 relations and 1.10 ms with 1,000. Before/after complete-render probes measured 0.59/0.69 ms with ten relations, 1.32/1.49 ms with 100 and 19.49/20.24 ms with 1,000. These batch timings preceded the display-position correction, whose extra measurement runs in graphical windows. In the actual GUI the final prototype's twenty cached redraws averaged 0.72 ms with a 1.46 ms maximum on the current demo model. Moving among graph buttons leaves buffer text unchanged and does not read metadata.
