# Completion quotes catalog identifiers

Issue #170 reports PostgreSQL completion inserting mixed-case catalog names without quotes, so the server folds them to a different name. Applying the completion case-style option to identifiers can likewise change which object SQL names.

Keep identifier candidates in catalog case and mark them with their insertion identity. Match their names without surrounding quotes, then call the existing `clutch-db-escape-identifier` on acceptance. This delegates to native MySQL backticks, PostgreSQL/SQLite double quotes and the existing JDBC dialect implementations instead of guessing backend folding or reserved-word rules in the completion engine. The backend may keep safe names bare, as ClickHouse does. Case style continues to apply to keywords only.

For generated qualified column candidates, preserve the qualifier as written in the query and escape the catalog column separately. For completion inside an existing quoted identifier, match the delimiter-escaped contents and replace the original outer quotes on acceptance, avoiding duplicate quotes and allowing unfinished quotes at point.

Regression coverage reproduces the original bare mixed-case insertion, checks quoted/unfinished identifiers, qualifiers, embedded quotes and keyword separation, executes completed SQL against an in-memory SQLite database, and checks JDBC dialect insertion without claiming live JDBC coverage.

Review of 49317cd found two executable PostgreSQL failures: an unquoted derived alias `AS Label` was inserted as `"Label"`, changing the name from `label`, and an uppercase `"SELECT"` column lost its identifier identity to an equal keyword candidate. Both were reproduced against a disposable OrbStack PostgreSQL database; control queries succeeded. The existing acceptance regression now covers both boundaries, quoted derived aliases and direct projection names.

Keep SQL-derived names distinct from catalog names using the existing candidate insertion identity: `(sql . TOKEN)` carries the original projection token through nested star expansion, so the database retains its own quoting and folding semantics. Catalog names continue to use backend escaping. Prefer identifiers over equal keyword candidates in column context while preserving keyword completion at the beginning of a statement, including leading comments. No backend folding table, new cache, protocol or persistent state is needed.

The first quote detector invoked the lexer for every character before point and copied through the end of the buffer. Search only possible quote/comment delimiters and copy only the current statement instead. Compiled Emacs 32 probes with warm metadata and statement caches measured 40 KB completion at 2.33 ms on main, 29.94 ms on the original PR, and 2.51 ms after this correction; 120 KB measured 6.57, 90.49 and 7.00 ms. These local CPU measurements are not network latency guarantees.

A single table-driven live regression calls the real completion command and executes its result for seven shapes on native PostgreSQL/MySQL and JDBC Oracle/SQL Server/file-backed DuckDB: mixed-case catalog names, reserved-word columns, quoted/unquoted aliases, direct projection names, nested stars and existing quotes. The earlier `Us` fixture was ambiguous with the `USER` keyword and opened a completion menu; `UserN` makes acceptance deterministic without bypassing the completion UI machinery.

The final follow-up gate passed on Emacs 29.4, 30.2 and 32 (950 passed, four skipped per version), including byte compilation, package-lint, checkdoc and architecture checks. The complete isolated native/JDBC matrix passed all 15 suites: 256 passed, 225 capability skips, zero failures, including the 35 original live cases and the four additional array/bracket/cold-prefix checks. Reversing identifier priority or escaping original SQL output tokens again independently makes the corresponding acceptance regression fail. Temporary containers and volumes were cleaned up; the production connections and installed plugin were untouched.

The fc359cd review found that treating every `[` as an identifier quote removed PostgreSQL array subscripts, and the old unquote helper left outer quotes on empty or doubled-delimiter prefixes passed to cold Oracle completion. Both faults first failed focused regressions. Brackets are now identifier quotes only on SQLite/SQL Server; the existing edit path directly decodes doubled delimiters without changing the shared SQL parser. The existing live matrix additionally executes array subscripts on PostgreSQL/DuckDB, bracket identifiers on SQL Server and a cold empty-prefix lookup on Oracle. Unique `IndexV` avoids stopping the batch fixture at an ambiguous `INDEX` keyword completion.

GitHub package-lint rejected the `rx any` form despite its support in Emacs 29: it matched the newer function name. A temporary checkout of current package-lint reproduced that failure on the old code and passed the equivalent `rx in` spelling. No minimum-version change, compat dependency or installed-package update is needed.

The final follow-up compiled CPU probe measured 2.37 ms for 40 KB and 7.12 ms for 120 KB with warm caches, retaining the performance correction without another cache or parser layer.
